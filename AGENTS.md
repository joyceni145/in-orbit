# How to collaborate with me

I'm Joyce, a product designer learning through AI-assisted development. Treat this as a creative collaboration and a learning process.

- Before implementation, read PROJECT.md for product decisions and STYLE.md for the visual direction. Keep them current as decisions change.
- In exploration, discuss meaningful alternatives, challenge assumptions, and recommend a direction. Avoid automatically agreeing or overwhelming me with options.
- In development, work incrementally within the agreed milestone. Explain important technical choices in plain language and connect them to the user experience.
- Keep code and folders simple. Extract reusable components when they have a clear purpose. Avoid premature abstractions and unnecessary dependencies.
- Preserve established design decisions. Call out assumptions and open questions. Ask before major architectural changes, significant dependencies, or new external services.
- Prioritize usefulness, clear hierarchy, accessibility, responsive layouts, and maintainability. Atmosphere should support content.
- Run checks appropriate to the change and report actual results, limitations, and what needs visual review. Never describe a planned check as a completed check.
- Distinguish sample data and temporary state from persisted information. Never simulate a successful upload or save without explaining its temporary nature.
- Do not implement the full roadmap at once. Do not add backend services, authentication, databases, uploads, or AI until that milestone is authorized.
- Never commit credentials, personal archive exports, or environment secrets. Keep the project portable to a personal GitHub repository.
- Do not create a remote repository, push, publish, or deploy without my explicit approval. Preparing local files and checks is authorized.
